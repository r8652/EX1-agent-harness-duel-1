# דוח: Study Planner, API מול SDK

בניתי את אותו סוכן (מתכנן לימודים) פעמיים: פעם עם harness שכתבתי בעצמי על ה-Messages API, ופעם על ה-Claude Agent SDK.
שתי הגרסאות משתמשות באותו קוד מתוך `shared/`: אותם 6 כלים, אותן סכמות ואותו system prompt.

## תנאי ההשוואה

- מודל `claude-opus-5-5` עם effort `medium` ו-thinking אדפטיבי בשתי הגרסאות.
- גרסאות הספריות נעולות ב-`requirements.txt`: `anthropic==1.17.0`, `claude-agent-sdk==0.2.170`.
- כל ריצה מוחקת את תיקיית המצב ומתחילה מאפס. סשן 2 רץ על מופע חדש של הסוכן שטוען את המצב מהדיסק.
- התרחיש: 7 פניות בשני סשנים, תאריך קבוע `2026-10-25`, ו-9 בדיקות pass/fail. רובן בודקות את מה שנשמר בקבצים (`tasks.json`, `memory.json`, `plan.json`) ולא את הטקסט של התשובה.

הטבלאות נבנו מקובצי התוצאות עם `python shared/report.py`.

## איפה ה-SDK עולה יותר טוקנים ואיפה פחות

ה-SDK עולה יותר בשלושה מקומות. הראשון הוא בסיס קבוע בכל קריאה: Claude Code עוטף את ה-system prompt שלי בטקסט משלו
ומגדיר את הכלים כשרת MCP (`mcp__planner__add_task` וכו'). גם תור עם קריאה אחת למודל, כמו `session2:3` ו-`session2:4`,
מגיע לבערך 3,500 טוקנים של prompt.

השני הוא הזיכרון. `CLAUDE.md` נטען בכל תור עם כל ההעדפות, בלי קשר למה שנשאל. ב-API נכנסות רק העדפות שקשורות להודעה
(עד 3, לפי מילים משותפות). בתרחיש שלי יש רק העדפה אחת אז ההבדל קטן, אבל ככל שהזיכרון יגדל זה יעלה יותר.

השלישי הוא קריאה שלא ביקשתי. בכל סשן Claude Code מריץ קריאה אחת ל-`claude-haiku-5-5`, בערך 1,200 טוקני קלט ו-13 עד 25 טוקני פלט.
זה עולה בערך $0.00014, כלומר כמעט כלום, אבל הקריאה הזו לא מופיעה ב-`usage` אלא רק ב-`model_usage`. בלי לבדוק את זה לא הייתי יודעת שהיא קיימת.

מצד שני, ה-SDK חוסך בכמה מקומות. ה-caching שלו אוטומטי ועובד טוב: 94% מה-prompt נקרא מה-cache, במחיר של $0.20 למיליון טוקנים במקום $4.
ב-API הייתי צריכה להחליט בעצמי איפה לשים את נקודות ה-`cache_control` ולשמור שתחילת הבקשה לא תשתנה בין קריאות.
בנוסף, אין בו קריאת סיכום בשיחה קצרה. הדחיסה של Claude Code מופעלת רק קרוב לסוף חלון ההקשר, ואילו ב-API הגדרתי סף נמוך
(9,000 טוקנים) כדי שהדחיסה תפעל גם בתרחיש קצר, וכל דחיסה היא עוד קריאה למודל. בשיחה ארוכה זה מתהפך, כי הסיכום חוסך טוקנים בכל קריאה שאחריו.
גם בלוק ה-`<context>` שנוסף ב-API לכל תור (תאריך, מצב המטלות, העדפות רלוונטיות) עולה כמה עשרות טוקנים בכל פעם.
ב-SDK התאריך נמצא פעם אחת ב-system prompt, שנשמר ב-cache.

פלט הכלים זהה בשתי הגרסאות (JSON קומפקטי, עד 8 שורות ואז `more`), אז הטוקנים שהכלים מוסיפים זהים.

## על מה הייתה לי שליטה ב-API ואיבדתי ב-SDK

- מה בדיוק נשלח למודל. ב-API אני בונה כל בקשה ויודעת בדיוק מה יש בה. ב-SDK יש טקסט של Claude Code שאני לא רואה ולא יכולה לשנות.
- איזה זיכרון נכנס. ב-API אני מסננת לפי רלוונטיות, ב-SDK `CLAUDE.md` נטען כולו.
- דחיסה. ב-API אני קובעת מתי לדחוס ומה הפרומפט של הסיכום. ב-SDK זה אוטומטי.
- caching. ב-API אני קובעת איפה הנקודות. ב-SDK זה אוטומטי, וכאן זה עבד טוב, אבל אי אפשר לשנות.
- מדידה. ב-API יש לי טוקנים לכל קריאה. ב-SDK יש רק סכום לתור, ו-`total_cost_usd` מצטבר לאורך כל הסשן.
  בהתחלה זה גרם לעלות לתור להיראות גבוהה פי 3, עד שהבנתי מה קורה ותיקנתי (`turn_cost`). גם קריאת ה-Haiku לא נראית ב-`usage`.
- שגיאות וגבולות. ב-API אני קובעת מה חוזר למודל כשכלי נכשל (`is_error`) ושמים גבול של 15 קריאות לתור. ב-SDK הכלי מחזיר `is_error`
  וה-SDK מעביר אותו הלאה, אבל אין לי גישה ללולאה עצמה.
- לוג. ב-API כל פעולה מודפסת עם שם הקובץ שביצע אותה. ב-SDK אני רואה רק את ההודעות שחוזרות.

מה שה-SDK נתן לי בלי לכתוב קוד: לולאה, caching, דחיסה, המשך שיחה עם `resume`, הרשאות לכלים, ושמירה על ההיסטוריה בלי לשנות אותה.
את הדבר האחרון היה צריך לממש בזהירות ב-API: ב-Opus 5.5 בלוקי ה-thinking קשורים לשיחה שבה נוצרו, ולכן ההיסטוריה ב-`history.py`
היא append-only, והדחיסה מחליפה את כל השיחה בסיכום ולא עורכת הודעות ישנות.

## איזו גרסה הייתי בוחרת

לסוכן הזה הייתי בוחרת ב-SDK. הוא עבר את כל הבדיקות, כולל שליפה מהזיכרון בסשן חדש ובקשה שסותרת העדפה שמורה.
הקוד שלו קטן בהרבה ואין לי מה לתחזק בלולאה, ב-cache או בדחיסה. בשימוש אישי הוא רץ על ה-login של Claude Code בלי מפתח נפרד,
והשיחות קצרות והזיכרון קטן, כך שהבסיס הקבוע של Claude Code נקרא ברובו מה-cache ולא עולה הרבה.

אם הסוכן היה משרת הרבה סטודנטים או צובר הרבה זיכרון, הייתי עוברת ל-API. במצב כזה כדאי לשלוט בדיוק במה שנכנס להקשר,
לסנן זיכרון לפי רלוונטיות ולמדוד עלות לכל קריאה, וזה בדיוק מה שה-SDK מסתיר.
